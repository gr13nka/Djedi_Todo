# Переработка экрана `/projects`

## Контекст

`/projects` — рабочее место для джедайских техник Дорофеева: выгрузить мысли о проекте в заметку, вытащить оттуда конкретные следующие действия, держать список проектов в порядке.

Решения, принятые в разборе:

| | |
|---|---|
| Главное | обзор и порядок в проектах; заметка и извлечение задач — второй шаг |
| Обзор | **доска** во всю ширину, `/projects` открывается ею; клик по карточке → экран проекта |
| Карточки | свободный размер, наложение разрешено; показывают имя и кусок заметки |
| Папки | **зоны** на холсте: подписанный прямоугольник позади карточек |
| Телефон | 2 колонки masonry, высота по длине заметки, как Google Keep; расположение не редактируется |
| Кнопка «дни без задач» | быстро включить, посмотреть, выключить |
| Устройства | широкий десктоп и Android |
| Объём | раскладка и взаимодействие — можно; модель данных Dexie и вокруг-синк — нельзя |
| Темы | оставить тёмными только Gruvbox Dark, Everforest Dark, Dracula; задать настоящую высоту |

История коммитов показывает корень: связку «строка заметки → задача» чинили семью точечными коммитами подряд (`c3aecbc`, `0958ae4`, `486b2ef`, `1e20047`, `4e5a08a`, `e579117`, `47b0966`) — механику доводили, раскладку не пересматривали.

Рубрика design-ui. 12 находок из 19, 7 минорных придержаны. Исходники прочитаны целиком; иерархия и плотность — по скриншоту; **контраст не измерен**, нужен запущенный app.

### Блокеры

Ушли с роута или уронили app, пока курсор в textarea — написанное исчезло; undo тоже только в памяти (`textUndo.ts:235`). На экране, смысл которого — записывать мысли, это потеря данных.

**2. Ни одно перетаскивание в приложении не работает на Android.** Весь DnD — нативный HTML5 (`taskDnd.ts`, `useReorderList.ts:68`, `TaskItem.tsx:76`, `SelectableTaskRow.tsx:355`), который с тача не запускается, полифила нет. Отдельно `FileTree.tsx:182-206` слушает только `mousemove`/`mouseup` — намеренно, HTML5 сломан в WKWebView (`:54`). Итог: на телефоне нельзя ни превратить строку заметки в задачу, ни переупорядочить задачи, ни разложить проекты по папкам. Ядро метода и заявленная главная задача — только на десктопе.

**3. `ProjectTabs.tsx` — крестик закрытия вкладки это `<span onClick>` внутри `<button>`.** Не фокусируется, не объявляется скринридером, вложенные интерактивные элементы невалидны.

**11. `FileTree.tsx:340-343` — контекстное меню `fixed` по сырым `clientX/clientY` без прижатия к вьюпорту.** У края экрана уезжает наружу, «Переименовать» и «Удалить» недостижимы.

**12. Инлайновые NEU-тени в тёмных темах не рисуют ничего.** `index.css:170-176` зануляет все `--shadow-raised*`/`--shadow-pressed*` в `transparent`; реальные значения только у `wax-pencil` (`:194-222`), и там 1 px хайрлайн. Карточки, нажатые вкладки, поднятые кнопки и вдавленная рамка заметки различаются только заливкой — причина плоскости скриншота. Стили инлайновые, поэтому Tailwind их не переопределит.

### Что уже хорошо — не трогать

- **Геометрический хит-тест строк** (`lineAtPoint`, `:407-421`) вместо `elementFromPoint` — только он заставляет ручки работать во время набора, когда превью `visibility:hidden`. На pointer-канал переезжает без изменений.
- **`lastAppliedDescRef`/`pendingExternalRef`** (`:117-159`) — глотает эхо live-query, чужое значение откладывается до blur. Вокруг-синк на этом держится.
- **Механика захвата в `useProjectCardLayout.ts`** — pointer, `setPointerCapture`, порог 4 px, `suppressClickRef`, `ResizeObserver`, коммит только по `endInteraction`. Заготовка общего примитива.
- **`can-hover:` вариант** — на тач-устройствах скрытые контролы становятся видимыми. Задокументировано в CLAUDE.md.

## Стратегия: сначала убрать, потом добавлять

**Три механики перетаскивания сводятся к одной.** Сейчас их три: HTML5 DnD, мышиные события в `FileTree`, pointer-события в `useProjectCardLayout`. Любая будущая работа с перетаскиванием пишется трижды; чтобы понять, почему дроп не сработал, надо знать, какая из трёх тут действует. Первая редакция этого плана добавляла **четвёртую** — параллельный тач-канал рядом с HTML5. Это добавление сложности ради предотвращения сложности.

Pointer-события покрывают мышь, тач и перо одним кодом и уже работают в проекте. Один примитив — порог, захват, долгое нажатие, координатный хит-тест, полезная нагрузка — заменяет три. Тач начинает работать везде сразу, а не тремя отдельными фичами; класс проблем `effectAllowed`/`dropEffect` исчезает вместе с HTML5. Риск честный — это рефакторинг системы, отлаженной семью коммитами, поэтому он идёт отдельным этапом до всех фич, с проверкой «на мыши как раньше» после каждого коммита.

**Редактор заметки делится.** `ProjectDraftEditor.tsx` — 746 строк на семь забот. Состояние документа (`localDesc`, undo, `saveDesc`, согласование внешних правок) уезжает в `hooks/useNoteDocument.ts`; после этого автосейв — правка в десять строк в хуке, а не внутри монолита.

**Что удаляется попутно:** настройка `projectGridEnabled` и второй режим сайдбара · обход коллизий `placeProjectCardFrame` и колоночная математика (`projectCardLayout.ts:23-28,91-108`) — холсту с наложением разводить нечего, и зонам тоже · дублирующее контекстное меню (`FileTree.tsx:336-367`) → `ui/ContextMenu.tsx` · `ProjectSelector.tsx`, `renderMarkdown`.

**Чего сознательно не делаю:** движка доски, конфигурируемой системы раскладок, абстракции над темами — абстракций с одним потребителем.

| | Сейчас | Станет |
|---|---|---|
| Место | сайдбар 280–640 px | вся ширина окна |
| Позиция | ячейка `{col, row}` | свободная `{x, y}` |
| Размер | шаг 72 px, спаны 1–4 / 1–3 | любой, минимум 160×72 |
| Пересечения | запрещены | разрешены, поверх — тронутая последней |
| Группировка | заголовки секций | зоны на холсте |
| Содержимое | иконка + обрезанное имя | иконка + имя + кусок заметки |
| Размер значит | ничего | сколько заметки видно |

Кусок заметки режется `stripMarkdown` (`utils/markdown.ts:94`) — сейчас мёртвый код, здесь получает потребителя.

**Кадр:** `{ x, y, w, h, z }`; `x`/`w` — доли ширины доски, `y`/`h` — пиксели, иначе раскладка едет при смене размера окна. `z` поднимается до максимума при захвате. `ProjectGridLayout` уже версионирован → v2, ячейки в доли, плюс ключ `folders`. Лежит в `DeviceSettings`, вокруг-синк не затрагивается.

Холст ограничен окном по ширине и растёт вниз; бесконечной панорамы не делаем — она требует миникарты, зума и «где я».

**Доступность:** холст мышиный по природе, клавиатурного пути двигать карточки не будет (его и сейчас нет, `useProjectCardLayout.ts:263-268`). Приемлемо только потому, что дерево остаётся полноценным путём к каждому проекту с клавиатуры.

### Зоны (папки)

Прямоугольник с подписью позади карточек, его можно двигать и тянуть. Перетащили карточку внутрь — сменился `folderId`; вытащили — стала беспапочной. Пространственное расположение и структура данных становятся одним и тем же, и доска делается самодостаточной для «наводить порядок».

- **Принадлежность — по левому верхнему углу карточки.** Одна точка, а не пересечение площадей: при разрешённом наложении «сколько процентов внутри» неотвечаемо.
- **Зоны тоже могут накладываться**, побеждает верхняя по `z`. Значит кода обхода коллизий не нужно нигде.
- **Перемещение зоны тащит карточки за собой** (принадлежность не меняется); **растягивание — нет** (пересчитывается). Иначе «подвинул рамку» молча меняло бы данные.
- **Папка без зоны** получает её автоматически на свободном месте — то же, что `reconcileProjectGridLayout` уже делает для карточек. **Смена папки извне** (дерево, телефон, синк) перебрасывает карточку внутрь новой зоны: `folderId` — синхронизируемая правда, координаты — местные.

Хранится там же: `projectGridLayout.folders[folderId] = { x, y, w, h, z }`, той же миграцией. Новой сущности нет.

### Кнопка «дни без задач»

Тумблер в шапке доски, по умолчанию выключен — вид «как в Keep» не засоряется. Включили — на каждой карточке строка «сколько дней по проекту не было задач».

Считаем `сейчас − max(createdAt, completedAt)` по неудалённым задачам проекта; задач не было никогда — от `Project.createdAt`. Именно эти метки, а не `Project.updatedAt`, потому что последний загрязнён с трёх сторон:

| | `Project.updatedAt` | `createdAt`/`completedAt` задачи |
|---|---|---|
| Правка метаданных (имя, цвет, папка) | бьёт | нет |
| Массовый `reorder` бампает все строки списка | бьёт | нет, пишется `sortOrder` |
| Вокруг-синк заменяет строку целиком по LWW (`vaultKinds.ts:185-194`) | бьёт | нет |

Форма — по прецеденту `hooks/useStalenessScore.ts`: хук владеет и числом, и тумблером, компонент только рисует. Цветом не кодируем — красный на этом экране занят под «нет следующего действия». Настройка `boardIdleDaysVisible` в `DeviceSettings`.

**Расположение на телефоне не редактируется — сознательно.** Раскладка device-local, поэтому перетаскивание не могло бы доехать до компьютера; дать жест и молча потерять его результат хуже, чем не давать. Позиции с десктопа не теряются, просто не применяются: мобильный рендер берёт из кадра только `y`.

**Смена папки с телефона доезжает** — `folderId` синхронизируется как обычная запись, а дерево после этапа 0 получает тач-перетаскивание. То есть на телефоне вы меняете, к какой группе относится проект, и на компьютере карточка оказывается внутри зоны этой папки. Переносимая часть перемещения переносится; device-local остаются только пиксели.

Тач-жесты появляются из этапа 0 сами: долгое нажатие 500 мс начинает перетаскивание — строки заметки, задачи, проекта в дереве. Одно правило на всё.

## Допущения и границы

- **«Следующее действие» = верхняя незакрытая задача по `sortOrder`** — та, что уже показывается первой в `ProjectTaskList.tsx:37`. Модель не меняется; используется только для признака «проект встал».
- **Синхронизация расположения карточек — вне объёма, решено отдельно.** Вокруг-синк везёт только объявленное в `vaultLayout.ts`, а `deviceSettings` исключён трижды — в `vaultLayout`, в `webExport.ts:10`, в `clearAllTables`/`snapshotAllTables`. Любой путь означал бы переезд поля в `UserSettings` либо новый vault-kind. Переезд дополнительно упирается в то, что трёхстороннее слияние настроек сравнивает поля через `===` и прямо документирует «настройки — скаляры, не объекты» (`threeWayMerge.ts:172-174`): вложенный объект раскладки всегда считался бы изменённым с обеих сторон и схлопывался в LWW, затирая доску целиком, без ошибки компиляции.
- **«Давность правки заметки» — вне объёма.** Более тонкий признак («думал, но задач не завёл») требует нового поля, миграции и правки сериализатора.
- **Скелетоны — вне объёма.** Примитива нет, чтения локальные, загрузка видна один кадр. Вместо этого — не мигать пустым состоянием на первом тике `useLiveQuery`.
- **Вне объёма также:** сортировка и фильтры доски, инлайн-редактирование вместо модалок, виртуализация, правило hover-reveal.
- **Anti-patterns: 1 совпадение** — эмодзи как иконки, это `Project.icon`, пользовательский контент, рядом всегда текстовое имя. Уходят два текущих: тултип с существенным содержимым и плейсхолдер вместо подписи.
